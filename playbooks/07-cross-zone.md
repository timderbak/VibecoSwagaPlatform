# Playbook 07 — Cross-zone request

Цель: попросить владельца чужой зоны внести изменение, нужное для твоей фичи.

## Когда нужно
Твоя фича требует изменения в файле, который **не** в твоей зоне (по `DEVELOPER.local.md`).

Примеры:
- Влад делает биллинг, нужно добавить поле в `User` (зона Стаса).
- Тим делает проекты, нужен новый компонент в `frontend/components/ui/` (общая зона).

## Что НЕ делать
- Не редактировать чужой файл «по-быстрому».
- Не убирать pre-commit hook.
- Не делать `git commit --no-verify`.
- Не аппрувить свой же PR за «коллегу».

## Как делать правильно

### Шаг 1: останови работу
Зафиксируй текущее состояние своей ветки (commit или stash).

### Шаг 2: создай GitHub-issue

Скажи Claude: «запроси у Стаса добавить is_billable: bool в User для биллинга».

Claude выполнит:
```bash
# 1. Найдёт владельца через .github/CODEOWNERS для пути
# 2. Создаст issue:
gh issue create \
  --title "[cross-zone] Dev #2 → Dev #3: backend/app/auth/models/user.py" \
  --body "**Запрос на изменение в чужой зоне.**

Файл: backend/app/auth/models/user.py
Причина: Add is_billable: bool to User for billing module integration

Владелец (CODEOWNERS): @stas

Когда сделаете — закройте issue с упоминанием PR (\`Closes #<N>\`)." \
  --label cross-zone-request \
  --assignee stas
```

Issue создаётся, Стасу прилетает уведомление.

### Шаг 3: продолжи свою работу с моком

Твой WP может временно использовать заглушку:
- В `service.py` добавить `# TODO: depends on cross-zone-request #<issue>`.
- В тесте — заюзать фикстуру с заглушкой.
- Не пытайся «обойти» — это создаст тех-долг.

### Шаг 4: отслеживай статус
В отчёте «что у нас?» входящие/исходящие cross-zone показываются (`gh issue list --label cross-zone-request --assignee @me`). После того как PR от овнера замержен в main:
1. Сделай `git pull && git rebase main` (Claude делает сам).
2. Убери `# TODO`-заглушку из своего кода.
3. Прогон тестов, коммит.

## Что должен сделать овнер (получатель запроса)

```
человек:  что у нас?
Claude: ... входящий cross-zone-запрос от Влада: добавить is_billable в User.
человек:  делаем
```

Действия:
1. Создать ветку `dev/<N>/cross-zone-<request-id>` от main.
2. Реализовать минимум: только то, что попросили (поле + миграция + при необходимости тест).
3. **Не** включать в коммит ничего лишнего.
4. PR с заголовком `feat(auth): add is_billable to User (cross-zone #<issue>)`.
5. Auto-merge.
6. Закрыть issue после мержа (или в commit message — `Closes #<issue>`).

## SLA
По договорённости команды (рекомендуется ≤ 24 часа). Если просьба простая — ответ в день обращения. Если требует обсуждения — отписать в issue, чтобы инициатор не ждал в неведении.
