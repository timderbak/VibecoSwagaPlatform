# Playbook 01 — Intake

Цель: собрать достаточный контекст, чтобы написать спеку.

## Когда запускается
- В начале нового проекта (репо пустой, нет `docs/spec.md`).
- Можно вызвать вручную: `/intake` или просто описать идею.

## Skill
`superpowers:brainstorming`

## Как вести интервью

Задавать вопросы по одному, мульти-чойс предпочтительнее открытых. Ответы фиксировать в `docs/intake.md`.

### Стандартный набор вопросов

1. **Что строим в одном предложении.**
2. **Кто пользователь.** (founder / executor / client / admin / другие)
3. **Главная боль пользователя.** Что он сейчас делает плохо/долго/руками.
4. **Главный сценарий happy path.** От «открыл» до «получил результат», 3-5 шагов.
5. **Сущности.** Какие основные объекты в системе (User, Project, …)?
6. **Внешние интеграции.** Stripe, Slack, S3, OpenAI, что-то ещё?
7. **Auth модель.** SSO / email+password / magic link / Supabase Auth?
8. **Multi-tenancy.** Один аккаунт = одна организация? Или per-user?
9. **Нефункциональные.** Latency, нагрузка, регуляторика, аптайм?
10. **Размер.** Неделя / месяц / квартал?
11. **Состав команды.** Сколько разработчиков? Кто за что отвечает?

### Признаки достаточного контекста
- Можешь сформулировать 3-5 главных пользовательских сценариев.
- Можешь перечислить ключевые сущности и их атрибуты.
- Понимаешь, какие внешние системы трогаются.

Если хоть одно «нет» — задавай ещё вопрос. Не торопись в спеку.

## Что записать в `docs/intake.md`

```markdown
# Intake — <название проекта>

## Что строим
<одно предложение>

## Пользователь и боль
<кто, что у него болит>

## Happy path
1. ...
2. ...

## Сущности
- User: ...
- Project: ...

## Интеграции
- Stripe (биллинг)
- ...

## Auth и tenancy
...

## Нефункциональные
...

## Состав команды
- Dev #1 — Тим
- Dev #2 — Влад
- Dev #3 — Стас
```
