# Playbook 13 — Integration Day

Цель: раз в неделю собрать всю команду, замержить готовые Submodules, прогнать end-to-end на staging, поймать интеграционные расхождения **раньше**, чем они станут болезненными.

## Зачем

В Mode B каждый Dev неделями работает в своей ветке. Без integration-точки баги интеграции копятся и проявляются разом в конце. Integration Day — **regular sync gate**.

## Когда

**Каждую пятницу в 14:00** (или другой день, по договорённости команды). Длительность — 1.5-2 часа.

## Участники

Все Dev #N. Не отменять без согласия всех. Если кто-то болеет — пропустить раз, но в следующий раз обязательно.

## Подготовка (за день до)

Каждый Dev:
1. Скажи Claude: `что у нас?`. Получишь сводку: ветка, последний коммит, открытые Features.
2. Реши: приносишь готовый Submodule одним PR или промежуточный прогресс?
3. Если готовый Submodule — за день до Integration Day создай PR (auto-merge **выключен**, чтобы не залетел до синка).
4. Если промежуточный — пуш `dev/<N>/<submodule>` для демо.

## Повестка Integration Day

### 1. Status round (15 минут)
Каждый по 5 минут:
- Что готово в его модуле
- Что в работе
- Какие cross-module нужны и от кого
- Какие риски/блокеры

### 2. Merge готовых PR'ов (30-60 минут)

Каждый PR который готов к мержу:
1. **Контракты не дрейфят** — `pytest tests/integration/test_contracts.py` зелёный
2. **Live-аппрувы** — остальные Dev'ы жмут approve в реальном времени (изменения в общей зоне — обязательны от всех; внутри модуля — owner сам решает, нужен ли second pair of eyes)
3. **Squash-merge в main** — одна команда, видим как замёржилось

Если PR конфликтует с main:
- Live-rebase (другие ждут или продолжают)
- Если сложный конфликт — переносим на следующий день, не блочим остальных

### 3. End-to-end smoke на staging (30 минут)

После мержей — **автодеплой на staging** (через `.github/workflows/staging-deploy.yml`).

На staging прогоняем golden path:
1. Логин (Profile)
2. Создать Project (Projects)
3. Добавить запись в финансы (Finances)
4. Подсмотреть в логи (Logs)
5. Спросить AI summary (AI)

Это **ручной тест втроём**. Что не работает — заводим issue с тегом `integration-bug` и приоритезируем.

### 4. Договорённости на следующую неделю (15 минут)
- Какой Submodule каждый закрывает к следующему Integration Day?
- Какие cross-module запросы нужны (создаём issues с понятным title и assignee на owner'а соответствующего модуля)?
- Какие RFC-PR в общую зону планируются (накапливаем, чтобы не делать их рассыпью)?

## Что фиксируется

После Integration Day Claude генерит `docs/integration-days/<YYYY-MM-DD>.md`:
```markdown
# Integration Day — 2026-05-15

## Статус модулей
| Module | Owner | Готово | В работе | Замержено сегодня |
|--------|-------|--------|----------|-------------------|
| Projects | Тим | 1.1, 1.2 | 1.3 | PR #42 (Submodule 1.2 целиком) |
| Finances | Влад | — | 2.1 | — |
| Profile + Logs + AI | Стас | 3.1 | 3.2 | PR #43 |

## Замёрженные PR'ы
- #42 feat(projects): submodule milestones
- #43 feat(profile): full RBAC

## Integration bugs обнаружены
- (issue #X) ...

## Договорённости на следующую неделю
- ...
```

Этот файл ассайнится каждому, идёт в общий чат.

## Если что-то идёт не так

**Сценарий: PR одного Dev'а конфликтует с PR другого.**
- Не паниковать. Live-rebase того, кто пришёл вторым.
- Если конфликт в общей зоне — это сигнал, что нарушены границы. Разобраться и поправить.

**Сценарий: contract test падает (контракт коллеги изменился).**
- Найти RFC-PR который это сделал. Понять зачем. Адаптировать свой код. Не накапливать долг.

**Сценарий: Integration bug на staging.**
- Issue с тегом `integration-bug`, приоритет critical/major.
- Решается в течение недели, **не отменяет** Integration Day следующей недели.

**Сценарий: Dev не успел подготовиться.**
- Один раз — простили. Второй раз — обсудить, не сломан ли процесс.

## Что НЕ делать

- ❌ Откладывать Integration Day "потому что не готовы". Лучше прийти с минимумом, чем накапливать.
- ❌ Мержить изменения общей зоны без явного approve остальных Dev'ов даже на Integration Day. Даже если все втроём в одной комнате.
- ❌ Делать "большой бах" раз в месяц — теряется смысл. Раз в неделю — sweet spot.
