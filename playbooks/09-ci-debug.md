# Playbook 09 — CI Debug

Цель: разобраться, почему CI красный, и починить — за ≤3 попытки. После 3-го фейла — stop-rule.

## Шаг 0: понять, что упало

```bash
gh run list --branch dev/<N>/<slice> --limit 1
gh run view <run-id> --log-failed
```

Категории фейлов:
1. **Тест упал** (90% случаев)
2. **Линтер ругается** (ruff/eslint)
3. **Билд не собрался** (Docker / npm install / pip install)
4. **Миграция не применилась** (alembic upgrade head падает)
5. **Контракт нарушен** (тест `test_contracts.py`)
6. **CODEOWNERS не аппрувнул** (не CI, но блокирует мерж)

## Шаг 1: попытка 1 — гипотеза по симптому

Прочитать сообщение об ошибке, выдвинуть гипотезу, сделать минимальный фикс.

### Тест упал
- Воспроизвести локально: `docker compose -f docker-compose.test.yml exec -T backend pytest <test-path> -v`.
- Если красный — фикс кода или теста.
- Если зелёный — возможно flaky test или env разница; проверить `docker-compose.test.yml` env vars.

### Линтер ругается
- `docker compose exec backend ruff check .` или `npm run lint`.
- Авто-фикс: `ruff check . --fix` / `npm run lint -- --fix`.

### Билд не собрался
- Локально: `docker compose build --no-cache backend`.
- Часто: новая зависимость не в `pyproject.toml` / `package.json`.

### Миграция не применилась
- `alembic history` — посмотреть последовательность.
- `alembic upgrade head` локально — точно ли проходит.
- Возможны: дубликат `revision`, циклическая зависимость, сырой SQL не для PostgreSQL.

### Контракт нарушен
- `tests/integration/test_contracts.py` сравнивает текущий OpenAPI с замороженным `docs/contracts/openapi.json`.
- Если ты намеренно изменил контракт — ты в нарушении §17. **Откатить и идти через RFC-PR.**
- Если случайно (например, сменил тип поля) — откатить изменение схемы.

## Шаг 2: попытка 2 — другой угол

Если попытка 1 не сработала, предположи **другую** причину. Не повторяй ту же гипотезу с другим значением.

Примеры смены угла:
- Тест падает → проверял код, не помогло → может, фикстура?
- Билд → проверял зависимости → может, версия Python/Node не та?
- Миграция → проверял версии → может, БД не пересоздана?

## Шаг 3: попытка 3 — изоляция

Попробуй воспроизвести минимальным тестом или скриптом. Локализуй до строчки.

## Шаг 4: STOP-RULE — Context7

Если три попытки не сработали — **СТОП**.

```
1. mcp__plugin_context7_context7__resolve-library-id <библиотека из ошибки>
2. mcp__plugin_context7_context7__query-docs <конкретный вопрос>
3. Прочитать релевантный раздел.
4. Сформулировать в чате:
   "Я застрял на <X>. Прочитал <раздел Y из docs>. Гипотеза: <Z>.
    Хочу попробовать <конкретное действие>. Пушать?"
5. Только после явного «да» от человека — попытка 4.
```

## Никогда

- 5-я, 6-я, 7-я попытка с вариациями. Это бездумный retry.
- `--no-verify`, `--force`, отключение тестов «временно».
- Закомментировать падающий тест.
- `try/except` вокруг проблемы вместо фикса.

## После починки

- Прогнать тесты локально → зелёные.
- Закоммить с понятным сообщением: `fix(<slice>): <what was broken and why>`.
- Пуш — CI должен стать зелёным.
