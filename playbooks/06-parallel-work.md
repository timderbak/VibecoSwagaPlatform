# Playbook 06 — Parallel Work (auto-pilot)

Цель: ежедневный цикл работы Dev #N в auto-pilot режиме.

## Утренний старт

```
человек:  claude
человек:  что у нас?
```

Действия Claude:
1. `git fetch origin main`.
2. Если main впереди — `git rebase origin/main`. При конфликте — см. `playbook 08-merge-conflict.md`.
3. Собрать сводный статус (как в `что у нас?`):
   - текущая ветка
   - незакоммиченные изменения
   - открытые PR'ы (свои)
   - входящие cross-zone-запросы (issue с тегом `cross-zone-request`, ассайн на меня)
   - reflexion findings (issues с тегом `reflexion-finding`, ассайн на меня)
4. Сводный отчёт человеку:
   ```
   Доброе утро.
   Ветка: dev/2/billing (3 коммита впереди main).
   Незакоммиченных нет, rebase clean.
   Открытых PR: 1 (PR-#42, ждёт CI).
   Входящих: 1 cross-zone от Влада в auth/.
   Reflexion findings: 0.
   Текущий WP по плану: WP-2.3 «subscription renewal».
   Продолжаем?
   ```

## Цикл работы над WP

```
человек:  продолжаем
```

Действия Claude:
1. Прочитать `docs/plan.md`, найти текущий WP.
2. Запустить `superpowers:test-driven-development`:
   - **RED:** написать failing integration test в Docker (`backend/tests/integration/<slice>/test_<wp>.py`).
   - Запустить: `docker compose -f docker-compose.test.yml exec -T backend pytest <path>` — должен упасть.
   - **GREEN:** написать минимум кода в `app/<slice>/`. Запустить тест — зелёный.
   - **REFACTOR:** причесать. Тесты остаются зелёными.
3. Прогнать всю пачку тестов своего слайса.
4. Если зелёное — `git add . && git commit -m "feat(<slice>): <wp-description>"`.
5. `git push origin dev/<N>/<slice>`.
6. Обновить статус WP в `docs/plan.md` (если этим занимается Claude — закоммить отдельным коммитом `docs: WP-X.Y done`).
7. Спросить: «Готово. Следующий WP или отдаём на ревью?»

## Отдача на ревью

```
человек:  отдавай
```

Действия Claude (запускает агента `.claude/agents/pr-checker.md`):
1. **Pre-PR check:**
   - все тесты зелёные в Docker
   - линтер чистый (ruff, eslint)
   - rebase на свежий main
   - проверка контрактов: тест `tests/integration/test_contracts.py` (см. `playbook 04`) проходит
   - граница не нарушена (pre-commit hook не сработал)
2. Если pre-check **красный** — фиксить (применять §5 stop-rule после 3 фейлов).
3. Если зелёный — `gh pr create`:
   ```
   gh pr create \
     --title "feat(<slice>): <wp-description>" \
     --body "Реализует WP-<N>.<M> из docs/plan.md.\n\nЗатрагивает: <slice>/**.\nКонтракты: не менялись.\n\n<auto-generated commit list>"
   ```
4. `gh pr merge --auto --squash <PR-N>`.
5. Сообщить: «PR #<N> создан. Auto-merge включён. Замержится сам, как CI зелёный (если только свой слайс) либо дополнительно после аппрувов CODEOWNERS общей зоны.»

## Аппрув входящих PR

```
человек:  что у нас?
Claude: ... PR-#43 от Влада ждёт твоего аппрува (затронут common/api.ts).
человек:  посмотри что там
```

Действия Claude:
1. `gh pr view 43 --json files,additions,deletions,commits`.
2. Кратко описать diff человеку: «Влад добавил поле `is_billable` в `User`, изменил миграцию. Тесты Стаса проходят (CI зелёный). Reflexion findings нет.»
3. Если человек говорит `аппрув 43`:
   ```
   gh pr review 43 --approve --body "approved"
   ```

**Никогда не аппрувить без явного «аппрув N» от человека.**

## Конец дня

Если есть незавершённые WP — `git stash` или `git commit -m "wip:..."` (с осознанным wip-prefix). Не оставлять «грязный» рабочий каталог.

## Раз в неделю — синк

```
человек:  синк-апдейт
```

Действия Claude (см. `.claude/commands/sync.md`):
1. Собрать данные: для каждого Dev из `docs/plan.md`:
   - текущая ветка (через GitHub API)
   - последний коммит и дата
   - открытые PR'ы
   - WP'ы из плана со статусом (готов / в работе / pending)
2. Вывести таблицу человеку для отправки в общий чат.
