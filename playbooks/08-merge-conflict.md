# Playbook 08 — Merge Conflict

Цель: разрулить конфликт при `git rebase main` или PR.

## Когда возникает

В правильно настроенной системе (CODEOWNERS + границы) конфликты случаются **только в общей зоне** (контракты, core/, components/ui/, docker-compose.yml). Если конфликт в твоём слайсе — что-то пошло не так (кто-то нарушил границы).

## Сценарий 1: rebase словил конфликт в общей зоне

Пример: Тим вчера обновил `docker-compose.yml` (общая зона), сегодня ты делаешь `git pull && rebase main`.

```bash
git rebase main
# CONFLICT (content): Merge conflict in docker-compose.yml
```

Действия Claude:
1. **НЕ** делать `git rebase --abort` рефлекторно.
2. Прочитать конфликт: `git diff`.
3. Если конфликт **прост** (разные секции YAML, не перекрывающиеся ключи) — мержим автоматически:
   - Берём обе стороны через `git checkout --theirs` / `--ours` для соответствующих участков, либо ручной merge.
   - `git add <file>`.
   - `git rebase --continue`.
4. Если конфликт **сложный** (изменение одного и того же ключа) — стоп, зови человека:
   ```
   "Конфликт в docker-compose.yml на ключе `services.backend.environment`.
    Тим вчера добавил X, ты сейчас добавляешь Y. Какое значение оставляем?"
   ```

## Сценарий 2: rebase словил конфликт в твоей зоне

Что-то пошло не так. Возможные причины:
- Кто-то нарушил CODEOWNERS (например, force-push или прямой коммит в main без PR).
- Ты сам нарушил границы и не заметил.

Действия Claude:
1. Стоп. Зови человека:
   ```
   "Конфликт в backend/app/billing/service.py — это твоя зона, никто не должен был
    туда писать. Возможно, нарушение CODEOWNERS. git log <file> покажет, кто."
   ```
2. Не пытайся разрулить автоматически — может быть симптом более серьёзной проблемы.

## Сценарий 3: PR не может быть смержен (mergeable=false)

GitHub auto-merge не сработал, потому что main ушёл вперёд.

Действия Claude:
1. `git fetch origin main`
2. `git checkout dev/<N>/<slice>`
3. `git rebase origin/main` — обычный сценарий 1.
4. `git push --force-with-lease` (это **единственный** случай, когда force допустим — на собственной ветке после rebase, и только `--force-with-lease`, не `--force`).
5. CI перезапустится, auto-merge доделает работу.

## Никогда

- `git push --force` (без `--with-lease`).
- `git rebase --abort` без анализа.
- `git reset --hard` для «починки» конфликта.
- Игнорировать конфликт через закоммит обоих вариантов одновременно.

## Если 3 раза подряд не получилось

Применяй `CLAUDE.md §5` stop-rule — Context7 / docs / гипотеза. Не «попробую ещё раз с другим флагом».
